# ClipSense MVP Stabilization

This note documents the critical stabilization work for the current MVP upload-to-analysis loop. It does not describe the future narrative intelligence roadmap.

Current status: ready for local verification/testing of the stabilized MVP path, not ready for the next product roadmap phase.

## Intake Model

ClipSense is designed around a unified intake model:

```text
source input -> stored source asset -> extracted video asset(s) -> metadata -> transcript -> analysis -> highlights/risk/context/storyline
```

Supported product intake types are:

- Public or user-provided video link.
- Direct uploaded video file such as `.mp4`, `.mov`, `.mkv`, `.webm`, or `.avi`.
- ZIP archive containing multiple video files.

The current stabilized MVP path implements only ZIP upload through the web UI and worker. This is an implementation limitation of the current pass, not the intended long-term product model. Link ingestion and direct single-video upload are intentionally not implemented in this stabilization task.

## What Was Fixed

- The Go API now keeps a Redis client and pings Redis explicitly during startup instead of assigning `Ping().Result()` into the client variable.
- `/api/health` now returns JSON with database and Redis health checks. It returns HTTP 503 if either dependency is unavailable.
- The Go API has local-development CORS for `http://localhost:3000` and `http://127.0.0.1:3000`, with `Authorization` and `Content-Type` headers allowed.
- Batch creation now returns an error if Redis enqueue fails and marks the batch as `failed` instead of silently leaving it stuck as `pending`.
- The Python worker now calls redis-py `BLPOP` with the correct argument order.
- The Python worker now safely extracts ZIP files without `extractall()`.
- ZIP handling now blocks absolute paths, path traversal, extraction outside the processing directory, too many files, and excessive decompressed video bytes.
- Non-video ZIP entries are ignored; only `.mp4`, `.mov`, `.mkv`, `.webm`, and `.avi` entries are extracted for processing.
- Docker web configuration now uses browser-accessible `http://localhost:8080` for `NEXT_PUBLIC_API_URL`.
- A root `.gitignore` now protects local env files, runtime data, uploads, database files, build outputs, caches, and model artifacts.
- CI now validates the Go API, Python worker syntax, web build, and Docker Compose configuration.

## How To Run Locally

From the repository root:

```bash
docker compose up --build
```

Then open:

- Web app: `http://localhost:3000`
- API health: `http://localhost:8080/api/health`

The web app registers/logs in against the Go API at `http://localhost:8080`. In the current MVP, uploading a ZIP creates a batch, writes the source archive to the shared Docker volume, enqueues a Redis job, and lets the worker extract supported video assets from the ZIP. Future link and direct-video intake should normalize into the same internal pipeline instead of creating separate downstream analysis paths.

## Required Environment Variables

Docker Compose provides the required service environment for the MVP stack:

- `API_ADDR`
- `DATABASE_URL`
- `REDIS_URL`
- `UPLOAD_DIR`
- `PROCESS_DIR`
- `WHISPER_MODEL`
- `QDRANT_HOST`
- `QDRANT_PORT`
- `NEXT_PUBLIC_API_URL`

For direct local runs outside Docker, start Postgres, Redis, and Qdrant yourself and use `.env.example` as the reference values. Set `JWT_SECRET` to a non-default value for any shared environment.

Optional local CORS override:

- `CORS_ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000`

## Known Limitations

- This is still an MVP stabilization pass, not a production hardening pass.
- The current web/API intake implementation accepts ZIP archives only. The product architecture is not ZIP-only; link and direct-video intake remain future work.
- The worker loads Whisper and SentenceTransformer models at startup, so first boot can be slow and network-dependent.
- Queue handling still uses a Redis list, not an acknowledged retry/dead-letter queue.
- Worker failures mark the batch as `failed`, but detailed error messages are logged only and are not yet persisted in the database.
- The storyline generator is still basic clustering/order logic, not advanced narrative intelligence.
- The API search endpoint was removed from the Go API because it depended on a Qdrant client API that did not match the pinned Go module and was not part of the current upload-to-analysis MVP path.
- `npm install --package-lock-only` reported 8 frontend dependency vulnerabilities. They were not auto-fixed in this pass because that can require broader dependency upgrades.
- `npm audit` currently reports 8 frontend dependency vulnerabilities: 1 moderate, 6 high, and 1 critical. The critical finding is against `next@14.1.4`; the suggested fix upgrades outside the current dependency range.
- `pip-audit` was installed and attempted against `apps/api/ai_worker/requirements.txt`, but it failed while building `openai-whisper` metadata because `pkg_resources` was missing inside the audit build environment.
- `govulncheck` could not run because Go is unavailable. `trivy` was not available. Docker Scout could not run because the Docker daemon is unavailable.
- Export upgrades, editor integrations, Rust video processing, platform imports, and enterprise features are intentionally out of scope.

## Test Coverage Added

- Go API tests cover health dependency failure JSON, local CORS preflight allow/reject behavior, missing/invalid auth rejection, and batch creation rejection when no file is provided.
- Python worker tests cover safe ZIP extraction for supported videos, ignored non-video entries, path traversal rejection, POSIX absolute path rejection, Windows absolute path rejection, excessive file count rejection, and excessive decompressed size rejection.

## Security Verification Notes

- ZIP traversal and absolute-path protections are covered by worker tests.
- Excessive file count and decompressed-size limits are covered by worker tests.
- Non-video ZIP entries are ignored by the extraction layer and covered by worker tests.
- API upload size is limited by `ParseMultipartForm(200 << 20)`.
- CORS is restricted to local development origins by default: `http://localhost:3000` and `http://127.0.0.1:3000`.
- Authenticated API routes reject missing or invalid tokens.
- Redis enqueue failures mark the batch as `failed` rather than silently leaving it `pending`.
- Worker processing failures are logged and mark the batch as `failed`, but detailed failure reasons are not yet persisted.
- `JWT_SECRET` defaults to `dev-secret` for local development only; set a non-default secret for any shared environment.

## Not Part Of This Task

- Advanced narrative arc scoring.
- Multiple storyline strategies.
- Director notes or explanation generation.
- Rust video engine.
- Twitch/YouTube/platform integrations.
- Enterprise authentication or workspaces.
- Production deployment automation.
- Export formats beyond the existing MVP batch export behavior.
